## What AXIOM is

Most open-source trading bots show you their best backtest. AXIOM is built around the
opposite instinct: **an idea does not ship unless it survives data it has never seen.**

Every strategy in this repo is run through a train/holdout split and walk-forward folds.
If it wins in-sample and loses out-of-sample, it is *rejected and the rejection is recorded
in this README* — see [Results](#results-proof). Four upgrades that looked great were killed
this way. One survived.

The second half of that discipline is the execution layer. Before any adapter is allowed near
a real venue it must pass a hermetic fault simulation: **10,500 assertions covering 35 failure
scenarios, 0 failures.** Rejected orders, timeouts, partial fills, slippage blowouts, and
duplicate sends all have to leave the account provably no worse off.

> **AXIOM ships with live trading disabled.** Every adapter is hard-gated behind `DRY_RUN=true`.
> Turning it off requires *two* independent actions (a config flag **and** a key), by design.

## Quick start

Two commands. No API keys required — the whole system runs on keyless public data.

```bash
git clone https://github.com/SAI141003/axiom.git && cd axiom

# 1) Backend
python3 -m venv .venv && ./.venv/bin/pip install -r requirements.txt

# 2) Frontend
cd frontend && npm install && npm run dev
```

Open **http://localhost:3000**.

### Prove it works (offline, ~15 seconds, no keys, no network)

```bash
./.venv/bin/python -m pytest tests/ -q          # 26 tests
./.venv/bin/python execution/scenario_sim.py 5  # 10,500 safety assertions
./.venv/bin/python -m backtest.octobot_engine   # walk-forward backtest
```

### Optional: add API keys

Everything above works with **zero keys**. Keys only unlock extras (LLM news
classification, HuggingFace model weights):

```bash
cp .env.example .env    # then fill in only what you want
```

`.env` is gitignored. See [Security](#security).

## Results (proof)

All numbers below are regenerated by the commands in [Quick start](#quick-start) and written to
`.data/*.json`. They are reproduced here verbatim — **including the losses.**

### 1. Safety proving ground — `execution/scenario_sim.py`

```
★ PERFECT — 10500 assertions, 0 failures.
```

35 scenarios × 300 runs across all three execution adapters (Hyperliquid, Solana/Jupiter, CCXT).
Eleven invariants are enforced:

| # | Invariant | Guarantees |
|---|---|---|
| I1 | paper-never-live | A dry-run order can never reach a venue |
| I2 | per-order cap | No single order exceeds `MAX_ORDER_USD` |
| I3 | daily cap | Cumulative daily spend is bounded |
| I4 | leverage clamp | Leverage is clamped, never amplified |
| I5 | slippage abort | Aborts spend nothing |
| I6 | in-tolerance fill | Fills land inside the quoted tolerance |
| I7 | reject → no spend | A rejected order costs $0 |
| I8 | timeout + idempotency | A resent order after timeout never double-fills |
| I9 | partial fill | Commits only the filled fraction |
| I10 | loss floor | Loss can never exceed capital committed |
| I11 | live requires 2 keys | Live needs the switch **and** a key |

### 2. Backtest — BTC/USD daily, 720 candles, fees 10bps + slippage 5bps

| Metric | Strategy | Buy & hold |
|---|---:|---:|
| Total return | **+44.21%** | +1.22% |
| Sharpe | **1.04** | — |
| Max drawdown | 17.34% | — |
| Win rate | 68.4% (19 trades) | — |
| Exposure | 30.4% of the time | — |

The edge is **downside protection**, not prediction: it is in the market only 30% of the time.

### 3. The honest part — where there is *no* edge

A 3-symbol × 3-timeframe sweep. **Only 2 of 9 cells have an edge:**

| Symbol | 1d | 4h | 1h |
|---|---|---|---|
| BTC/USD | ✅ +44.2% | ❌ −9.7% | ❌ −7.3% |
| ETH/USD | ✅ +34.2% | ❌ −6.8% | ❌ −0.7% |
| SOL/USD | ❌ −22.2% | ❌ −25.7% | ❌ −0.9% |

**Conclusion shipped in the code: this strategy family is daily-only.** Intraday loses.
SOL loses outright (though it still beat a −47% buy-and-hold).

### 4. Four upgrades tested → three rejected

This is the part most repos delete. Each was implemented, measured, and killed:

| Upgrade | In-sample | Out-of-sample | Verdict |
|---|---|---|---|
| **Weight tuning** (400 iters) | Sharpe **1.74** vs 1.05 ✨ | −1.38 vs −1.21 | ❌ **Rejected** — overfit |
| **Regime switching** | +26.5% return | beat buy&hold 2/3 vs 3/3 | ❌ **Rejected** |
| **Volume Profile** (VPOC/VAH/VAL) | — | +9.0% vs +18.7% | ❌ **Rejected** |
| **Per-symbol routing** | positive | −18.5% vs −15.3% | ❌ **Rejected** — overfit |
| **Order flow** (OBV + MFI) | — | matched default, better robustness | ✅ **Shipped** |

Machine-written verdicts, straight from `.data/`:

```
optimize_report.json  → "tuned beat default on train but NOT on holdout
                         — kept default (no overfit shipped)"   shipped: false
per_symbol_report.json→ "per-symbol routing does NOT beat both globals
                         out-of-sample — it's overfit to the train window."
```

### The strategy framework

Modeled on OctoBot's architecture, implemented natively:

```
Evaluator  →  Strategy  →  TradingMode  →  Adapter
(a signal)   (weighted     (enter/exit    (gated
             blend)        hysteresis)     execution)
```

Eight evaluators ship: RSI, MA-cross, Momentum, Mean-reversion, Bollinger, OBV, MFI,
Volume Profile. The shipped blend is a 7-component weighted vote.

### The dashboard

33 pages — backtest lab, scenario proving ground, venue map, order-flow monitor,
per-bot pages, macro data desk, trade journal.

## Safety model

Live trading is off, and it takes deliberate effort to turn on.

```bash
DRY_RUN=true            # master switch — the default
HL_MAX_ORDER_USD=5      # per-order cap
HL_DAILY_CAP_USD=20     # daily cap
HL_MAX_LEVERAGE=3       # leverage clamp
HL_SLIPPAGE_BPS=50      # abort threshold
```

Layers: **dry-run master switch → per-order cap → daily cap → leverage clamp →
slippage abort → idempotency keys → provable loss floor.**

Design notes:
- Live execution requires **both** `DRY_RUN=false` **and** a separately-provided key (invariant I11).
- Recommended posture is a **trade-only API key that cannot withdraw**.
- The Solana live swap-send path is **deliberately left unwired**.
- Loss is bounded by capital committed, and this is machine-verified 300×.

## Security

This repo is scanned to contain **no credentials**.

- `.env`, `.env.*`, `*.pem`, `*.key`, and `frontend/.env.local` are **gitignored**
- `.env.example` ships **placeholder names only** — every value is empty
- No private keys, wallet keys, or exchange keys are committed anywhere
- Secrets are loaded at runtime via `pydantic-settings` and are **never logged or printed**

If you fork this: keep `.env` out of git, and prefer **trade-only keys without withdrawal
permission**.

> ⚠️ Note: some prediction-market venues (e.g. Polymarket) are geoblocked in certain
> jurisdictions including Canada. AXIOM's venue catalog records reachability per venue and
> does **not** attempt to circumvent any geographic restriction.
